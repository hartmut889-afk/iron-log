# 鐵日誌

個人健身課表與訓練紀錄。單一 HTML 檔、沒有後端、沒有帳號、沒有追蹤。

**打開就能用：** https://hartmut889-afk.github.io/iron-log/

## 它能做什麼

- **一到日的課表**：週曆選日期，或在課表區左右滑動換日
- **記錄最大重量與組數**：每組填重量 × 次數，練完打勾。最大重量與估算 1RM（Epley 公式）會從所有打勾的組數自動算出來
- **配重建議**：依估算 1RM 給力量／肌力／增肌／代謝／熱身五種重量組數搭配，點一下直接套用
- **40 個動作的資料庫**：每個動作有解剖透視插畫（皮膚半透明、目標肌群發亮）、出力方向、目標肌群、動作要領、常見錯誤與呼吸節奏
- **課表範本**：內建推日／拉日／腿日，也能把任何一天存成自己的範本
- **離線可用**：第一次打開後就會快取，健身房沒訊號也能開

## 資料存在哪裡

**存在你自己的瀏覽器裡（localStorage），不會上傳到任何地方。** 這代表：

- 換手機、換瀏覽器、清除瀏覽器資料 → 資料不會跟著走
- 無痕視窗、或把頁面嵌在沙箱 iframe 裡 → 根本存不了。這種情況頁面頂端會出現紅色警告，**不會安靜地把資料吃掉**
- 想搬家或備份：設定 → 匯出備份檔，換裝置後用「從檔案還原」

程式每天第一次存檔時會自動留一份前一天的快照，主檔壞掉時會自動回復。

## 加到手機主畫面

- **iPhone**：Safari 開啟 → 分享 → 加入主畫面
- **Android**：Chrome 開啟 → 選單 → 安裝應用程式

加完之後會像一般 App 一樣全螢幕開啟。

## 想自己改一份

整個程式就是 `index.html` 一個檔案，沒有 build 步驟。Fork 之後改完推上 `main`，GitHub Actions 會自動部署到你自己的 Pages。

動作資料在檔案裡的 `DB` 陣列。

## 動作插畫

`img/*.webp` 的 40 張解剖透視圖是用 Gemini（`gemini-3-pro-image`）生成的，腳本與提示詞在
`scripts/gen-exercise-art.mjs`。為了讓整組風格一致，做法是先生一張「風格基準圖」，之後每張都把
基準圖一併送進去做風格條件化 —— 40 張各自獨立生成的話，配色與人物比例會整組走鐘。

```bash
GEMINI_API_KEY=... node scripts/gen-exercise-art.mjs [動作id ...]   # 生成 → img/
REF_IMAGE=img/src/bench.png ...                                     # 指定現成的基準圖
node scripts/optimize-art.mjs 0.82                                  # img/src/*.png → 600×800 webp
```

原始 PNG 留在 `img/src/`（14.7 MB），網站實際載入的是壓過的 WebP（合計 0.94 MB）。

**AI 生圖不是一次就對。** 硬舉試了四次（槓一直跑到身體後方，後來乾脆缺手臂）才改用構圖較單純的
站姿鎖定位；上斜推舉與前蹲舉則是被「平板臥推」的基準圖帶偏，得拿掉基準圖才畫對。要重生某張圖時，
先看它是不是被基準圖拉往錯的方向。

插畫載不到時（離線還沒快取、檔案漏掉），`artLayer()` 會退回 `figureSVG()` 即時算出來的人形示意圖 ——
關節角度一律是「畫面角度」：0 朝下、90 朝右、180 朝上。自訂動作也走這條路。
